Платформизация

Замена функциональности на публичные платформы​

MiniLMS — система для создания мини-курсов, назначения их группам и отслеживания прогресса. Core-ценность продукта — это связка «курс → тест → прогресс → отчёт». Всё, что к этой связке не относится, можно спокойно отдать готовым решениям.

1. Аутентификация → Auth0​

Что есть сейчас. Самописный вход по email/паролю (POST /auth/login), хранение хэшей (NFR-SEC-01), защита от перебора (NFR-SEC-04), четыре роли RBAC (learner / author / coordinator / admin). Всё это нужно писать, тестировать, латать дыры самим.

Чем заменить. Auth0 — Identity-as-a-Service. Бесплатный тариф до 7 500 MAU, нам хватит с запасом (NFR-CAP-01: до 1 000 зарегистрированных).

Как подключить:

  • На фронте — Auth0 SDK, пользователь логинится через готовую форму, получает JWT.

  • На бэке — middleware для проверки JWT вместо самописной логики.

  • Роли задаются в Auth0 через встроенный RBAC, передаются в токене как custom claim.

  • Защита от перебора, блокировка аккаунтов, MFA — идут из коробки, не пишем руками.

Выгода: убираем из кода хранение паролей и логику сессий. Бонусом получаем SSO и социальные логины.

2. Хранение файлов → AWS S3​

Что есть сейчас. Вложения к урокам (PDF, изображения) лежат на диске сервера (/uploads/lessons/{lessonId}/{fileName}), раздаются через nginx. Метаданные — в реляционной БД. Переход на S3/MinIO уже заложен в документе «Хранение данных» как путь масштабирования.

Чем заменить. AWS S3 (или MinIO для on-premise).

Как подключить:

  • При загрузке (POST /files/upload) бэкенд кладёт файл в S3-бакет через AWS SDK.

  • В таблице attachments вместо локального пути сохраняем S3-ключ.

  • Для скачивания генерируем presigned URL с ограниченным TTL — слушатель качает напрямую из S3, не нагружая наш сервер.

  • Перед бакетом ставим CloudFront (CDN) для быстрой раздачи.

Выгода: снимаем с бэкенда нагрузку на раздачу файлов, получаем безлимитное хранилище с репликацией и версионированием.

3. Уведомления (email / push) → SendGrid + FCM​

Что есть сейчас. Только внутрисистемные уведомления (таблица notifications, типы: course_assigned, deadline_soon, overdue). Email и push — пока в roadmap.

Чем заменить. SendGrid для email, Firebase Cloud Messaging (FCM) для push.

Как подключить:

  • SendGrid: при наступлении события (назначение, дедлайн, просрочка) бэкенд вызывает SendGrid API с шаблоном и данными. Доставка, retry, защита от спама — на их стороне.

  • FCM: если появится мобильное приложение — бэкенд отправляет push через FCM API с токеном устройства.

  • Внутрисистемная лента уведомлений остаётся в нашей БД — она привязана к прогрессу и является частью core-логики.

Выгода: не настраиваем SMTP, не боремся со спам-фильтрами, не пишем retry. Бонусом — аналитика открытий и доставки.

Стратегия платформизации​

Почему MiniLMS платформизуем​

MiniLMS по факту уже посредник между тремя сторонами: автор создаёт курсы, координатор назначает и контролирует, слушатель проходит обучение. Это классическая платформенная модель — ценность в том, что все три стороны работают в одном месте с единым процессом.

Модель бизнеса: B2B2C​

MiniLMS продаётся компании (B2B-сделка), а конечный потребитель — сотрудник этой компании (Consumer). Компания платит, сотрудник учится.

Почему не B2C — продукт заточен под корпоративное обучение (группы, назначения, дедлайны, отчёты координатора). Одиночному пользователю проще зайти на Coursera.

Почему не чистый B2B — конечный потребитель всё-таки живой человек, его UX напрямую влияет на успех продукта. Поэтому B2B2C точнее.

Монетизация: подписка (SaaS)​

Ежемесячная подписка с тарифами по количеству пользователей:

ТарифЦенаЧто включеноДля кого
Free0 ₽20 пользователей, 5 курсовПробный вход, НКО, мини-команды
Team4 990 ₽/мес100 пользователей, безлимит курсов, email-уведомленияМалый бизнес, учебные группы
Business14 990 ₽/мес500 пользователей, SSO, API, white-labelСредний бизнес, франшизы
EnterpriseИндивидуальноБез ограничений, on-premise, SLAКрупные компании

Почему подписка, а не другие модели:

  • Продажа доли — никогда нельзя исключать этот вариант, но при продаже доли есть риск потерять контроль над продуктом;

  • Плата за запуск (pay-per-use) — LMS используется постоянно, клиент будет демотивирован «счётчиком». Подписка честнее и предсказуемее для обеих сторон.

Что нужно доделать для платформизации​

  • Мультитенантность — изоляция данных между компаниями-клиентами (каждый — отдельный tenant).

  • Биллинг — интеграция с платёжной платформой (Stripe / ЮKassa) для автоматического приёма оплат.

  • Админка платформы — управление тенантами, тарифами, лимитами.

  • Публичный API — чтобы клиенты могли встроить MiniLMS в свои HR-системы.

  • White-label — кастомизация бренда (логотип, цвета, домен) для тарифов Business+.

Итог: core MiniLMS (курсы, тесты, прогресс, отчёты) — пишем сами. Вспомогательное (авторизация, файлы, рассылки) — отдаём готовым платформам. Сам MiniLMS продаём как B2B2C SaaS по подписке, целясь в малый и средний бизнес.
