# Глоссарий

| Термин | Определение |
|--------|-------------|
| **Слушатель (Learner)** | Пользователь, который проходит назначенные курсы и сдаёт тесты |
| **Автор (Author)** | Пользователь, который создаёт и публикует курсы |
| **Координатор (Coordinator)** | Пользователь, который управляет группами, назначает курсы и просматривает отчёты |
| **Админ (Admin)** | Координатор с полным доступом ко всем функциям системы |
| **Курс (Course)** | Набор уроков и тестов, объединённых одной темой. Может быть в статусе «Черновик» или «Опубликован» |
| **Урок (Lesson)** | Единица учебного контента внутри курса: текст, ссылки, вложения |
| **Тест (Test)** | Набор вопросов, привязанный к уроку. Один урок — один тест |
| **Попытка (Attempt)** | Зафиксированный факт сдачи теста: ответы, баллы, результат. Неизменяема |
| **Назначение (Assignment)** | Связь пользователя с курсом: кто, какой курс, в какой группе, с каким дедлайном |
| **Группа (Group)** | Набор пользователей, которым можно массово назначить курс |
| **Прогресс (Progress)** | Информация о том, сколько уроков пройдено из общего количества |
| **Дедлайн** | Крайний срок завершения курса. При просрочке статус меняется на «Просрочен» |
| **RBAC** | Role-Based Access Control — управление доступом на основе ролей |
| **JWT** | JSON Web Token — токен авторизации, передаётся в заголовке `Authorization: Bearer <token>` |
| **OpenAPI** | Стандарт описания REST API в формате YAML/JSON (ранее Swagger) |
| **ADR** | Architecture Decision Record — документ фиксации архитектурного решения |
| **RFC** | Request for Comments — документ-предложение для обсуждения до принятия решения |
| **MVP** | Minimum Viable Product — минимально жизнеспособный продукт |
| **Contract First** | Подход, при котором сначала создаётся API-контракт (спецификация), а потом код |
| **Docs as Code** | Подход, при котором документация хранится и версионируется как код (Git, Markdown, CI/CD) |
