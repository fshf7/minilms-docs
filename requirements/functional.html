Функциональные требования

UC-01 — Вход в систему​

ID: UC-01 Акторы: Пользователь (Учащийся / Автор / Координатор / Админ) Предусловия: пользователь зарегистрирован; аккаунт активен.

Основной поток:

  1. Пользователь открывает страницу входа.

  2. Вводит email и пароль.

  3. Система валидирует формат и проверяет учетные данные.

  4. Система создаёт сессию и открывает главную страницу по роли.

Постусловия: пользователь авторизован; доступы определены ролью.

Альтернативные потоки:

  • A1 (на шаге 3): неверный пароль → ошибка, вход не выполнен.

  • A2 (на шаге 3): аккаунт заблокирован → отказ во входе, сообщение причины.

Исключительные потоки:

  • E1 (на шаге 3): сервис авторизации недоступен → сообщение “попробуйте позже”, вход не выполнен.

Бизнес-правила:

  • Права доступа определяются ролью (RBAC).

UC-02 — Создание курса (черновик)​

ID: UC-02 Акторы: Автор Предусловия: автор вошёл в систему.

Основной поток:

  1. Автор выбирает “Создать курс”.

  2. Вводит название, описание (опц.), категорию (опц.).

  3. Система создаёт курс в статусе Черновик.

  4. Система открывает редактор курса.

Постусловия: курс создан и доступен автору для редактирования.

Альтернативные потоки:

  • A1 (на шаге 2): название пустое/слишком длинное → подсказка, создание запрещено.

Исключительные потоки:

  • E1 (на шаге 3): ошибка сохранения (БД недоступна) → курс не создан, сообщение об ошибке.

Бизнес-правила:

  • Черновик нельзя назначать учащимся/группам.

UC-03 — Добавление урока в курс​

ID: UC-03 Акторы: Автор Предусловия: есть курс (Черновик или Опубликован); автор — владелец курса.

Основной поток:

  1. Автор открывает курс и выбирает “Добавить урок”.

  2. Указывает название урока.

  3. Добавляет контент: текст, ссылки, вложения (файлы).

  4. (Опц.) Меняет порядок уроков в программе.

  5. Нажимает “Сохранить”.

  6. Система сохраняет урок и показывает его в программе курса.

Постусловия: урок создан/обновлён и виден в программе курса.

Альтернативные потоки:

  • A1 (на шаге 3): файл превышает лимит → файл отклонён, урок сохраняется без этого файла.

  • A2 (на шаге 5): автор отменил сохранение → изменения не применяются.

Исключительные потоки:

  • E1 (на шаге 3/5): пропал интернет/ошибка бэка → система показывает ошибку, данные урока остаются на форме до перезагрузки страницы (чтобы автор мог повторить сохранение).

Бизнес-правила:

  • “Пустой урок” допускается, но при публикации курса система предупреждает о пустых уроках.

UC-04 — Создание теста к уроку (автопроверка)​

ID: UC-04 Акторы: Автор Предусловия: урок создан; автор — владелец курса.

Основной поток:

  1. Автор открывает урок → “Добавить тест”.

  2. Задаёт параметры: проходной балл; лимит попыток (опц.).

  3. Добавляет вопросы типов MVP: один вариант / несколько вариантов / короткий текст.

  4. Для вопросов задаёт правильные ответы и баллы.

  5. Нажимает “Сохранить тест”.

  6. Система сохраняет тест и привязывает к уроку.

Постусловия: тест сохранён и готов к прохождению.

Альтернативные потоки:

  • A1 (на шаге 5): в тесте нет вопросов → сохранить как “готовый” нельзя; сохранить можно только как черновик.

Исключительные потоки:

  • E1 (на шаге 6): ошибка сохранения → тест не изменён, сообщение об ошибке.

Бизнес-правила:

  • Каждая попытка теста фиксируется (дата/время, ответы, балл, результат “зачёт/незачёт”).

UC-05 — Публикация курса​

ID: UC-05 Акторы: Автор Предусловия: курс создан; у курса минимум 1 урок.

Основной поток:

  1. Автор нажимает “Опубликовать”.

  2. Система проверяет минимальную готовность (название курса, минимум 1 урок).

  3. Система меняет статус курса на Опубликован.

Постусловия: курс доступен координатору для назначения.

Альтернативные потоки:

  • A1 (на шаге 2): нет уроков → публикация запрещена, показывается причина.

  • A2 (на шаге 2): есть пустые уроки → публикация возможна, но система показывает предупреждение.

Исключительные потоки:

  • E1 (на шаге 3): ошибка обновления статуса → курс остаётся в прежнем статусе.

Бизнес-правила:

  • Назначать можно только опубликованные курсы.

UC-06 — Создание группы и назначение курса группе с дедлайном​

ID: UC-06 Акторы: Координатор (или Админ) Предусловия: курс опубликован; координатор авторизован; пользователи существуют.

Основной поток:

  1. Координатор создаёт группу (название).

  2. Добавляет пользователей в группу.

  3. Выбирает “Назначить курс” → выбирает курс.

  4. Указывает дату старта (опц.) и дедлайн (опц.).

  5. Подтверждает назначение.

  6. Система создаёт назначения курса всем участникам группы.

  7. Система создаёт внутрисистемные уведомления “Назначен курс”.

Постусловия: у пользователей появился курс со статусом “Назначен”; дедлайн сохранён; уведомления созданы.

Альтернативные потоки:

  • A1 (на шаге 2): группа пустая → назначение запрещено.

  • A2 (на шаге 4): дедлайн раньше даты старта → система просит исправить.

  • A3 (на шаге 6): курс уже назначен части пользователей → система не создаёт дубликаты; сообщает “часть назначений уже существовала”.

Исключительные потоки:

  • E1 (на шаге 6): сбой при массовом назначении → система должна либо:

    • (вариант A) создать назначения атомарно “всё или ничего”, либо

    • (вариант B) создать частично и показать список ошибок. Для MVP выбрать вариант A (проще и предсказуемее).

Бизнес-правила:

  • Статусы прохождения: назначен / в процессе / завершён / просрочен.

UC-07 — Прохождение урока и теста учащимся (с сохранением прогресса при сбоях)​

ID: UC-07 Акторы: Учащийся Предусловия: курс назначен; учащийся авторизован.

Основной поток:

  1. Учащийся открывает список назначенных курсов.

  2. Открывает курс → видит программу и прогресс.

  3. Открывает урок → изучает материалы.

  4. Если у урока есть тест — запускает тест.

  5. Учащийся отвечает на вопросы.

  6. Система локально автосохраняет ответы в браузере (черновик) после каждого ответа.

  7. Учащийся нажимает “Отправить”.

  8. Система отправляет ответы на бэкенд, получает результат (балл, зачёт/незачёт) и показывает его.

  9. Система фиксирует попытку и обновляет прогресс по уроку/курсу.

Постусловия: попытка сохранена; прогресс обновлён.

Альтернативные потоки:

  • A1 (на шаге 4): попытки закончились → тест недоступен, показана причина.

  • A2 (на шаге 4): у урока нет теста → учащийся может нажать “Отметить урок пройден” (если включено).

Исключительные потоки (важно):

  • E1 (на шаге 5–7): пропал интернет → система показывает “соединение потеряно”; ответы остаются в черновике; учащийся может повторить отправку после восстановления связи.

  • E2 (на шаге 7–8): бэкенд недоступен/ошибка 5xx → результат не рассчитывается; ответы остаются в черновике; учащийся может повторить отправку позже; лимит попыток не уменьшается, пока не получено подтверждение сохранения.

  • E3 (на шаге 8): таймаут ответа сервера → считается как “не подтверждено”; ответы остаются в черновике; учащийся повторяет отправку; система должна избегать дублей (см. бизнес-правила).

  • E4 (на шаге 2–8): сессия истекла → требуется повторный вход; после входа черновик теста на этом устройстве доступен.

Бизнес-правила:

  • Если дедлайн прошёл, а курс не завершён → статус “Просрочен”.

  • Повторная отправка после таймаута не должна создавать дубликат попытки: отправка идёт с идентификатором черновика (idempotency).

UC-08 — Просмотр отчёта по курсу/группе (с пагинацией как ФТ)​

ID: UC-08 Акторы: Координатор (или Админ), Автор (только по своим курсам) Предусловия: есть назначения; у актора есть право на отчёт.

Основной поток:

  1. Актор открывает “Отчёты”.

  2. Выбирает курс и группу (или курс и список назначенных).

  3. Система показывает список пользователей и их статусы (назначен/в процессе/завершён/просрочен) с пагинацией (например, по 50 строк).

  4. Система показывает агрегаты: сколько начали, сколько завершили, сколько просрочили.

  5. (Опц.) Актор применяет фильтр по статусу.

Постусловия: отчёт просмотрен; данные доступны для управления (если в MVP предусмотрено).

Альтернативные потоки:

  • A1 (на шаге 2): нет данных → показывается пустой отчёт без ошибки.

  • A2 (на шаге 3): актор листает страницы отчёта → система догружает следующую страницу.

Исключительные потоки:

  • E1 (на шаге 3–4): ошибка формирования отчёта → сообщение об ошибке; предлагается повторить.

Бизнес-правила:

  • Автор видит отчёты только по своим курсам; координатор — по своим группам; админ — всё.

UC-09 — Внутрисистемные уведомления о назначении и дедлайнах​

ID: UC-09 Акторы: Система, Учащийся, Координатор Предусловия: создано назначение курса; (опц.) задан дедлайн.

Основной поток:

  1. При назначении курса система создаёт уведомление “Назначен курс”.

  2. За N дней до дедлайна система создаёт уведомление “Скоро дедлайн”.

  3. В день дедлайна/после система создаёт уведомление “Просрочено”, если курс не завершён.

  4. Учащийся открывает список уведомлений и отмечает прочитанным.

Постусловия: уведомления сохранены; статус “прочитано/непрочитано” обновлён.

Альтернативные потоки:

  • A1 (на шаге 2): дедлайн не задан → уведомления о дедлайне не создаются.

  • A2 (на шаге 4): пользователь не заходил в систему → уведомления остаются непрочитанными.

Исключительные потоки:

  • E1 (на шаге 1–3): фоновая задача уведомлений не выполнилась → уведомления создаются при следующем успешном запуске; система не должна создавать дубликаты.
