# Нефункциональные требования

## Безопасность и приватность

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-SEC-01 | Пароли хранятся только как стойкий хэш; восстановление — только через сброс | H |
| NFR-SEC-02 | Весь трафик по HTTPS; токены не передаются по HTTP | H |
| NFR-SEC-03 | RBAC на сервере: проверка прав на каждом защищённом API-запросе | H |
| NFR-SEC-04 | Ограничение частоты попыток входа + временная блокировка после N неудачных попыток | M |

## Производительность

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-PERF-01 | p95 времени ответа API для ключевых операций ≤ 2 сек (при нагрузке пилота) | H |
| NFR-PERF-02 | Отчёт по группе до 50 человек формируется ≤ 0.5 сек (p95) | H |

## Надёжность и восстановление

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-REL-01 | Доступность ≥ 99% в период пилота (кроме плановых работ) | M |
| NFR-REL-02 | Ежедневный бэкап БД; 7 копий; RPO ≤ 24ч, RTO ≤ 4ч | H |

## Ёмкость (Capacity)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-CAP-01 | До 1 000 зарегистрированных, 300 активных/нед, 100 курсов, 20 уроков/курс, 10 000 попыток/мес | M |

## Масштабируемость

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-SCAL-01 | Бэкенд stateless; допускается несколько экземпляров за балансировщиком | L (MVP) |

## Наблюдаемость (Observability)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-OBS-01 | Структурные логи + метрики: % ошибок 5xx, время ответа (p95), количество входов и отправок тестов | M |

## Удобство использования (Usability)

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-UX-01 | ≥ 80% новых пользователей в пилоте проходят путь «курс → урок → тест» без инструктажа | H |
| NFR-UX-02 | Основные сценарии работают при ширине экрана от 360px | M |

## Совместимость

| ID | Требование | Приоритет |
|----|-----------|-----------|
| NFR-COMP-01 | Корректная работа в последних версиях Chrome / Firefox / Safari / Edge | M |

| NFR-MAINT-02 | Автотесты на критичные ограничения: доступ по ролям, лимит попыток, фиксация попытки | M |
