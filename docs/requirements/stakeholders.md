# Стейкхолдеры и RACI

## Ключевые стейкхолдеры

| Стейкхолдер | Роль в проекте |
|-------------|---------------|
| **PO (Product Owner)** | Утверждает продуктовые решения и релиз |
| **Координатор обучения** | Владелец процесса назначения, дедлайнов и контроля. Проводит UAT |
| **Автор курса** | Консультирует по структуре обучения и текстам уведомлений |
| **Руководитель подразделения** | Задаёт требования к дисциплине и отчётности |
| **Учащийся** | Конечный пользователь; даёт обратную связь по UX |
| **Системный аналитик** | Формализует требования, сценарии, бизнес-правила |
| **Техлид / архитектор** | Принимает технические решения, отвечает за качество |
| **Команда разработки** | Реализует UI и backend |
| **QA** | Покрывает позитивные/негативные/граничные кейсы |
| **DevOps** | Развёртывание, фоновые задачи, мониторинг |
| **ИБ / Юрист** | Контролирует ПДн, доступы, журналирование |

## RACI-матрица

Функционал: «Назначение курса группе + дедлайн + уведомления»

| Активность | PO | Координатор | Автор | Техлид | QA |
|------------|:--:|:-----------:|:-----:|:------:|:--:|
| Определить правила назначения | C | **A** | C | I | I |
| Согласовать UX назначения | **A** | C | C | I | C |
| Спроектировать модель данных и API | I | C | I | **A/R** | I |
| Реализовать backend | I | I | I | **R** | I |
| Реализовать frontend | I | C | I | **R** | C |
| Тестирование | I | C | I | I | **R** |
| Приёмка (UAT) | **A** | **R** | I | I | I |
| Развёртывание | I | I | I | I | **R** |

> **R** — Responsible (делает), **A** — Accountable (отвечает за результат), **C** — Consulted, **I** — Informed.
