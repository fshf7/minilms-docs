## UC-02 — Создание курса

**Акторы:** Автор  
**Предусловия:** пользователь авторизован с ролью «Автор».

**Основной поток:**
1. Автор нажимает «Создать курс»
2. Вводит название и описание курса
3. Система создаёт курс в статусе «Черновик»

**Постусловия:** курс создан и доступен автору для редактирования.

**Альтернативные потоки:**
- A1 (шаг 2): название пустое/слишком длинное → подсказка, создание запрещено

**Исключительные потоки:**
- E1 (шаг 3): ошибка сохранения (БД недоступна) → курс не создан, сообщение об ошибке

**Бизнес-правила:** черновик нельзя назначать учащимся/группам.

## UC-03 — Добавление урока в курс

**Акторы:** Автор  
**Предусловия:** есть курс (Черновик или Опубликован); автор — владелец курса.

**Основной поток:**
1. Автор открывает курс → «Добавить урок»
2. Указывает название урока
3. Добавляет контент: текст, ссылки, вложения
4. (Опц.) Меняет порядок уроков
5. Нажимает «Сохранить»
6. Система сохраняет урок в программе курса

**Альтернативные потоки:**
- A1 (шаг 3): файл превышает лимит → файл отклонён, урок сохраняется без него
- A2 (шаг 5): автор отменил → изменения не применяются

**Бизнес-правила:** пустой урок допускается, но при публикации система предупреждает.

## UC-04 — Создание теста к уроку

**Акторы:** Автор  
**Предусловия:** урок создан; автор — владелец курса.

**Основной поток:**
1. Автор открывает урок → «Добавить тест»
2. Задаёт проходной балл и лимит попыток (опц.)
3. Добавляет вопросы: один вариант / несколько вариантов / короткий текст
4. Задаёт правильные ответы и баллы
5. Нажимает «Сохранить тест»
6. Система сохраняет тест и привязывает к уроку

**Бизнес-правила:** каждая попытка фиксируется (дата, ответы, балл, результат).

---

## UC-05 — Публикация курса

**Акторы:** Автор  
**Предусловия:** курс создан; минимум 1 урок.

**Основной поток:**
1. Автор нажимает «Опубликовать»
2. Система проверяет готовность (название + минимум 1 урок)
3. Статус курса меняется на «Опубликован»

**Постусловия:** курс доступен координатору для назначения.

---

## UC-06 — Назначение курса группе

**Акторы:** Координатор  
**Предусловия:** курс опубликован; группа существует и непустая.

**Основной поток:**
1. Координатор выбирает курс и группу
2. (Опц.) Задаёт дедлайн
3. Система создаёт назначения для всех участников группы
4. Система создаёт уведомления о назначении

**Альтернативные потоки:**
- A1: группа пустая → ошибка
- A2: дедлайн раньше даты старта → ошибка
- A3: курс уже назначен всем → информационное сообщение

**Бизнес-правила:**
- Статусы: назначен / в процессе / завершён / просрочен
- `UNIQUE(user_id, course_id)` — нельзя назначить дважды

## UC-07 — Прохождение урока и теста

**Акторы:** Учащийся  
**Предусловия:** курс назначен; учащийся авторизован.

**Основной поток:**
1. Учащийся открывает список назначенных курсов
2. Открывает курс → видит программу и прогресс
3. Открывает урок → изучает материалы
4. Запускает тест (если есть)
5. Отвечает на вопросы
6. Система автосохраняет ответы в браузере (черновик)
7. Нажимает «Отправить»
8. Система фиксирует попытку и обновляет прогресс

**Исключительные потоки:**
- E1: пропал интернет → ответы в черновике, повтор после восстановления
- E2: ошибка сервера → лимит попыток не уменьшается до подтверждения
- E3: таймаут → идемпотентность через `X-Idempotency-Key`

**Бизнес-правила:** если дедлайн прошёл, а курс не завершён → статус «Просрочен».

## UC-08 — Просмотр отчёта по курсу/группе

**Акторы:** Координатор (или Админ), Автор (только свои курсы)

**Основной поток:**
1. Актор открывает «Отчёты»
2. Выбирает курс и группу
3. Система показывает список пользователей и статусы с пагинацией (по 50 строк)
4. Система показывает агрегаты: начали / завершили / просрочили
5. (Опц.) Фильтр по статусу

**Бизнес-правила:** автор видит только свои курсы; координатор — свои группы; админ — всё.

## UC-09 — Внутрисистемные уведомления

**Акторы:** Система, Учащийся, Координатор

**Типы уведомлений:**
- Назначение курса
- Напоминание о приближении дедлайна
- Просрочка курса
